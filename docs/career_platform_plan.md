功能范围、技术路线与五人任务分工

**项目目标**

在现有计算机职业指导平台上，形成“岗位与企业数据—职业匹配—简历优化—岗位面试—练习复盘”的连续体验。五名成员各自负责一个可演示的功能模块，并通过统一数据结构、接口约定和端到端验收完成集成。

|              |                                                                                                                          |
|--------------|--------------------------------------------------------------------------------------------------------------------------|
| **实施重点** | **方案摘要**                                                                                                             |
| 数据基础     | 建设岗位 JD、企业基础资料和结构化面试题库；优先使用合规、可追溯的数据来源。                                              |
| AI 功能      | 用 NLP 处理简历与岗位文本，再由大模型生成有依据、可编辑的简历建议；面试阶段用 RAG 检索题库并生成岗位相关问题。           |
| 训练闭环     | 保存每次练习的题目、回答、反馈和时间，提供列表、详情与总结；“再答一次”和前后对比列为选做。                               |
| 课程落点     | 在功能实现中呈现算力、数据、算法与通信的协同，将数据处理、特征工程、模型评估和参数调优落到岗位推荐、简历匹配与面试检索。 |

# 一 项目现状与优化目标

项目已具备 Vue 3 前端、Django REST Framework 后端、MySQL 与 LanceDB 等基础，并包含职业推荐、简历管理、LangGraph 面试代理和语义搜索相关能力。本方案优先复用这些模块，补齐数据质量、岗位匹配、简历辅助、面试知识检索和历史复盘之间的业务连接。现有模块是否已完整可用，应在开发首周由对应成员核对接口和页面后确定。

本轮交付以可运行的课程项目 MVP 为准：允许用户选择已有岗位或粘贴 JD；核心流程不依赖外部招聘平台实时抓取；AI 输出必须能追溯到用户输入或题库证据，重要内容由用户确认。

# 二 目标用户流程

1.  数据准备：管理员或采集任务导入岗位 JD、企业公开资料和面试题库；清洗、去重、分类标注来源、采集时间与授权状态，并形成可供推荐、简历匹配和面试 RAG 使用的结构化数据。

2.  职业与岗位匹配：用户填写兴趣、技能和偏好，系统结合结构化条件与文本语义给出岗位建议，并展示匹配原因及待补足技能。

3.  简历辅助：用户选定目标岗位或粘贴 JD，系统抽取岗位要求并与简历内容对照，生成缺项提示、可改写建议和依据；用户审阅后再应用到简历。

4.  岗位面试：用户选择岗位及题目范围，RAG 从题库检索相关题目和参考要点，生成或编排问题；用户作答后获得基于回答内容的反馈。

5.  结束复盘：保存本次题目、实际回答、逐题反馈和时间；生成总结并供用户查看练习列表与详情。

建议先稳定最小数据模型，再接入数据源。字段命名和主外键由成员一牵头，其他成员按约定共同使用；原始文本与清洗后的结构化字段分开保存，便于更新、审计与问题排查。

|                        |                                                                                                                                                         |                                                       |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------|

| JobPosting 岗位        | id、title、company_id、city、salary_range、experience、education、description、skills、source、source_url、collected_at、valid_until、permission_status | 岗位搜索、职业推荐、JD 对照和面试计划。               |
| Company 企业           | id、name、industry、city、website、public_profile、source、source_url、verified_at                                                                      | 企业信息展示和岗位归属；只存业务所需公开信息。        |

## 数据来源与采集边界

- 岗位 JD：首选公开 API、明确允许使用的数据集、企业招聘官网公开页面或人工整理的样例；每条记录保留来源链接、采集时间、授权/许可状态和去重键。

- 企业数据：优先企业官网、政府或行业公开名录、企业公开招聘页，以及经许可的开放数据。企业评价、联系人、员工个人信息不作为本轮抓取目标。

- 关于 BOSS 直聘：不把直接爬取作为默认方案。先核对平台服务条款、robots 规则、数据许可和技术限制；未取得授权时改用官方合作/API、企业官网、开放数据或手工录入的演示样例。不得绕过登录、验证码或访问控制。

- 面试题库：整理来源清晰的自编题、开放许可题或团队创作题；保存题目来源和许可说明。避免复制受版权保护的付费题库或个人面试记录。

| 成员 | 主责模块 | 主要工作与边界 | 交付与验收 |
| --- | --- | --- | --- |
| 成员1 / 岗位、企业与面试题库数据 | 岗位 JD、企业资料、面试题库的采集/导入、清洗与基础 schema | 确定岗位、企业和面试题字段及来源登记；在合规前提下采集或导入岗位 JD、企业公开资料和面试题；完成文本清洗、去重、分类（岗位/知识点/难度）、标签化、来源与授权状态记录；提供岗位和题库查询接口，为成员4的 RAG 提供稳定数据。不绕过登录、验证码或访问控制。 | 能导入至少一组合法岗位、企业和面试题样例；岗位可按城市/方向筛选，题目可按岗位/知识点/难度检索；每条记录有来源和时间；重复记录不会重复入库。 |

| 成员3 / 简历 NLP 与大模型 | JD/简历解析与建议生成 | 用 Python 完成文本清洗、段落切分、技能/经历/教育等特征抽取；将结构化结果与 JD 要求对齐；调用后端已配置的大模型生成缺项提醒和改写建议；设计用户预览、编辑、确认后写回。 | 给定简历和 JD 可返回技能匹配、证据片段、缺项与改写建议；模型输出不凭空增加经历/指标；用户确认前不覆盖原简历。 |

# 五 技术路线与模块接口

以现有 Django 后端作为数据与权限边界，Vue 页面通过 REST API 调用业务能力。文本检索优先复用 LanceDB/现有语义搜索能力；MySQL 保存业务实体、原始来源、用户数据和会话记录。大模型密钥只放在后端配置中，前端不得接触密钥。

|                |                                                                                        |                                                                                                                                    |
|----------------|----------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| **链路**       | **处理步骤**                                                                           | **结果与约束**                                                                                                                     |
| 岗位数据       | 来源读取/人工导入 → 字段校验 → 清洗去重 → MySQL 保存 → 索引更新                        | 可筛选岗位与企业；记录 source、时间和许可；异常不阻断人工样例导入。                                                                |
| 简历优化       | 用户简历/JD → Python NLP 清洗与特征抽取 → 技能/经历对齐 → LLM 生成建议 → 用户确认      | 建议携带原文依据和目标岗位快照；模型只改写或提示，不虚构事实；保存确认后的版本。                                                   |
| 面试 RAG       | 岗位/知识点 → 题库检索 → 相关性过滤 → 问题与参考要点 → 用户回答 → 基于证据反馈         | 优先检索题库并显示题目来源；无证据时明确说明，允许通用追问但标识为生成内容。                                                       |
| 复盘记录       | 会话逐题事件 → 保存 AnswerRecord → 会话结束聚合总结 → 列表/详情展示                    | 服务端绑定登录用户；保留时间戳、题目快照和反馈；支持后续删除/导出策略扩展。                                                        |
| 模型评估与调优 | 岗位/简历/面试评估集 → 特征与检索参数 → 模型或排序结果 → 指标计算与人工抽样 → 参数记录 | 使用 Precision、Recall、F1、相关性、命中率和人工评分衡量效果；保留基线、数据集版本、参数、模型版本和实验结论，确保调优结果可复现。 |

## 公共接口约定

- 统一使用稳定 ID 和时间字段；岗位、题目和面试记录对外返回同一字段命名、错误格式和分页方式。

- 创建面试时保存目标岗位快照；即使原岗位 JD 后续更新，历史记录仍能还原当时依据。

- RAG 返回检索片段、题目 ID、来源和相关度；面试反馈接口保留真实回答以及所引用的证据。

- 模型调用失败时保留用户输入和面试流程状态，给出可理解的错误提示；允许题库/静态样例完成基本演示。评估记录需保留数据集版本、指标、参数和实验时间，便于复现调优结论。

## 端到端验收清单

- 岗位与企业数据可导入、搜索和追溯来源；题库可按岗位与知识点过滤。

- 用户以目标 JD 优化简历，看到依据明确的建议，编辑并确认后才保存。

- 用户以目标岗位开始面试，问题来自题库检索或明确标注的生成内容；完成回答后收到引用回答内容的反馈。

- 结束面试后能查看总结、练习列表和详情，包含用户、问题、回答、反馈和时间。

- 使用不同账号验证简历和面试历史隔离；演示数据不包含未经授权的个人敏感信息。

- 课程展示能够说明算力、数据、算法、通信如何协同，并演示特征工程、模型评估、参数调优和效果对比。

选做功能建议顺序：先实现“再答一次”，将原题和两次回答关联；再实现同一知识点的前后对比，突出回答结构、关键点覆盖和反馈变化。两项都依赖基础练习记录稳定后再开展。
